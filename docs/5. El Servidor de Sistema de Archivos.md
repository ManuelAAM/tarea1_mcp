# **5. El Servidor de Sistema de Archivos (FS)** 

Como desarrollador de software y creador de aplicaciones, constantemente se manipula una gran cantidad de archivos: desde repositorios enteros de código, clases de interfaces, hasta configuraciones de dependencias. En este contexto, al implementar agentes inteligentes en un equipo de trabajo, es vital el realizar una distinción técnica importante: **el término "FS" (File System o Sistema de Archivos) no es una parte constitutiva del protocolo MCP ni de su especificación oficial** . Más bien, es simplemente uno de los muchos servidores MCP de referencia que se han construido en código abierto para demostrar cómo conectar un modelo a recursos locales de manera estandarizada (Anthropic, 2024). Para ilustrarlo, la industria suele referirse al MCP como el "USB de la IA"; siguiendo esta analogía, el servidor FS es apenas uno de los múltiples conectores que puedo "conectar" para darle nuevas capacidades a mi modelo. 

Las herramientas que este servidor expone al modelo de lenguaje son esencialmente las mismas operaciones de sistema operativo que se ejecutarían manualmente en terminal: 

- Listar el contenido de un directorio. 

- Leer el contenido y metadatos de los archivos. 

- Escribir o sobrescribir código en archivos existentes. 

- Crear nuevos archivos o carpetas de directorios. 

- Mover archivos de ruta. 

- Buscar archivos específicos por nombre o patrón regular. 

**La delimitación del alcance y su importancia crítica:** Como cliente e integrador de esta tecnología, al levantar un servidor, el protocolo obliga a delimitar su alcance; es decir, se debe pasar por parámetros los directorios específicos que le están permitidos leer y modificar. 

¿Por qué existe y se exige este límite? Porque los sistemas agénticos modernos, gracias a sus enormes capacidades, ya no solo "piensan" o predicen texto; ahora **hacen** y ejecutan tareas lógicas y de planeación de forma autónoma (IBM, 2021). Si este límite no existiera y el servidor FS se ejecutara desde la raíz (/) de mi máquina, el modelo de inteligencia artificial tendría acceso indiscriminado a todo mi disco duro, por ejemplo. Esto significaría que ante un simple error de interpretación matemática, o una alucinación (un resultado sintético incorrecto), el modelo podría sobrescribir la configuración de mi sistema operativo, o peor aún, leer y exponer mis claves privadas (como tokens de bases de datos o 

credenciales de la nube), dejando información privada y sensible expuesta y potencialmente comprometiéndola.
