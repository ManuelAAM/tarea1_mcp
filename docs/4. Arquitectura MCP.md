# **4. Arquitectura MCP** 

Para que MCP funcione, la arquitectura se divide estrictamente en tres roles (Host, Cliente y Servidor). En una implementación del sistema de archivos local, los roles son los siguientes: 

- **El Host:** Es la aplicación principal donde yo (el usuario) interactúo. Puede ser un IDE (como Google Antigravity). 

- **El Cliente MCP:** Es un componente interno dentro del _Host_ que mantiene la conexión 1:1 con los servidores. Inicia la comunicación y enruta los mensajes. 

- **El Servidor MCP:** Es el programa ligero que expone las capacidades locales (en nuestro caso, acceso seguro al disco). _Es un error decir que el modelo accede directamente al disco; lo hace pidiéndoselo al Cliente, quien se lo pide al Servidor._ 

## **Primitivas del Servidor (Lo que expone al modelo):** 

1. **Herramientas (Tools):** Acciones ejecutables que el modelo puede invocar (ej. "escribir archivo", "ejecutar script"). Tienen nombre, descripción y esquema de parámetros. 

2. **Recursos (Resources):** Datos estáticos o dinámicos que el modelo puede leer para obtener contexto (ej. un esquema de base de datos o el contenido de un log). No alteran el estado. 

3. **Plantillas de Prompt (Prompts):** Instrucciones preconfiguradas que el servidor ofrece para guiar al modelo en tareas específicas de ese dominio. 

## **Primitivas del Cliente:** 

- **Roots:** Definen los límites del espacio de trabajo físico que el servidor tiene permitido entender y operar. 

- **Sampling / Elicitation:** Permite al servidor solicitar al modelo que genere texto o evalúe una condición basándose en un contexto específico proporcionado por el servidor. 

## **Transportes:** Existen dos transportes principales definidos por el protocolo: 

- **stdio (Standard I/O):** Utilizado para servidores locales. El _Host_ arranca el servidor MCP como un proceso hijo y se comunican a través de las entradas y salidas estándar del sistema operativo. 

- **SSE / Streamable HTTP:** Utilizado para servidores remotos, permitiendo la comunicación sobre redes mediante Server-Sent Events y HTTP POST.
