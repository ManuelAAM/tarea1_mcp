# **7. Casos de Uso y Aplicación de MCP** 

Al investigar las características clave de los LLM actuales, sabemos que pueden comprender jerga coloquial, generar código en múltiples lenguajes y realizar análisis de software sin necesidad de un entrenamiento fino y costoso (Microsoft, 2024). Sin embargo, la magia real ocurre cuando combinamos esta inteligencia pura con la capacidad de acceder dinámicamente a herramientas externas mediante MCP (Red Hat, 2026). 

A continuación, se presentan tres herramientas reales que están implementando esta tecnología hoy en día: 

1. **Google Antigravity:** Es un entorno de desarrollo agéntico avanzado y maduro, el cual es un ejemplo totalmente válido y pertinente. Si como usuario yo solicito, "Refactoriza la arquitectura de vistas en la aplicación y corrige los problemas de asincronía", Antigravity actúa como el _Host_ MCP. Se encarga de levantar un servidor local que lee mi código fuente; el agente razona sobre los cambios, y utiliza el servidor local para planificar, aplicar y guardar los arreglos directamente sobre las carpetas y archivos locales, resolviendo problemas a nivel proyecto. 

2. **Claude Code Desktop App (con integraciones de servidor MCP):** Esta aplicación de escritorio desarrollada por Anthropic cuenta con soporte nativo para servidores locales (Anthropic, 2024). Como usuario, puedo configurarle un servidor de GitHub o de Google Drive. Esto le permite al modelo, de forma autónoma, recuperar documentos en tiempo real de estas plataformas sin tener que salir del chat, realizar tareas complejas sobre datos actualizados y brindarme conclusiones orquestadas. 

3. **Zed (o IDEs impulsados por IA como Cursor):** Son editores de código modernos que han adoptado tempranamente el protocolo. A través de implementaciones MCP, estas herramientas le permiten a los agentes de IA tener el contexto absoluto de mi espacio de trabajo local (Sakura Sky, 2025). 

Nota de rigor técnico: Es fundamental cuidar la precisión al nombrar estas herramientas. "Qwen", por ejemplo, es una destacada familia de modelos de lenguaje subyacentes, pero no es una plataforma de desarrollo ni una herramienta final que integre agentes de desarrollo local, por lo cual considerarla como herramienta de MCP sería un error de concepto. 

## **¿Cómo estas herramientas editan repositorios completos sin subidas manuales?** 

Históricamente, los modelos sufren por límites estrictos en el tamaño de su ventana de contexto y el aislamiento de datos (AWS, s.f.). Sin embargo, gracias a MCP, ya no es necesario el copiar múltiples archivos fuente y pegarlos en un cuadro de texto en el navegador, o subirlos manualmente uno por uno. Digamos que, cuando solicito un cambio por ejemplo, el IDE inicia el cliente MCP. El modelo de inteligencia artificial utiliza la herramienta listar_directorio para explorar la estructura de mi proyecto. Luego, invoca la herramienta leer_archivo solo en las clases específicas que le interesan, optimizando el uso de _tokens_ . Tras realizar su cómputo de inferencia y generar el código nuevo, el modelo llama a la herramienta escribir_archivo. El servidor MCP ejecuta la acción escribiendo el nuevo código directo en mi disco local. Finalmente, yo simplemente abro mi panel de control de Git, reviso visualmente los _diffs_ o diferencias aplicadas y hago el _commit_ , automatizando de manera brillante la escritura local. 

Podemos ver que de esta manera podemos utilizar los modelos LLMs de una manera mucho más eficiente, donde, logra tener acceso a ciertos archivos, mediante supervisión y confirmación de lectura y escritura de archivos, y, en aplicaciones de desarrollo de software, por ejemplo, tiene múltiples aplicaciones para poder analizar y modificar múltiples archivos sin necesidad de proporcionarlos manualmente, uno por uno.
